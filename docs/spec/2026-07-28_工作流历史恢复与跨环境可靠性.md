## 3. 范围

- Workflows 中间窗口提供 Run history、运行详情和完整时间线。
- 查看 Prompt、Conclusion、Review、Decision、Artifact 和用户动作。
- 支持脱敏 Markdown 与 JSON 导出。
- Runtime 启动后恢复所有非终态 Run。
- 建立 delivery、Transition、Event 和完成通知的幂等与去重。
- 处理 Runtime 断连、重连、迟到消息、身份变化和不确定交付。
- 验收本机、SSH、Runtime Host、Git Worktree 和 Folder Workspace。
- 处理长 Prompt、长结论、大 Artifact、远程 Artifact 和 Host 隔离。
- 验证现有普通启动、Agent Activity 和无 Workflow 用户不受回归影响。

## 4. 非目标

- 不实现跨无关项目的 Workflow。
- 不实现仓库级模板导入、导出或团队共享。
- 不默认导出 Terminal transcript、凭据、环境变量或未脱敏内容。
- 不自动同步远程 Artifact 到本机路径。
- 不自动提交、推送、合并、删除分支或清理 Worktree。
- 不把断连直接等同于任务失败。
- 不承诺未列入兼容矩阵的新 Host 类型。

## 5. 实现合同

### 5.1 Run history

历史列表支持：

- 按 Project、Workspace、模板、状态和时间筛选。
- 显示模板版本快照、根目标、开始/结束时间和最终结果。
- 打开已归档模板创建的历史 Run。
- 区分活动 Run、等待用户、失败、取消和完成。

运行详情按单调递增 Event 序号展示：

- 节点和轮次
- Agent Assignment
- 实际 Prompt
- 完整最终结论
- Artifact Revision
- Review Aggregate
- Decision
- 状态变化
- 用户动作

时间线基于持久化 Event，不从当前 UI 状态反推。删除或归档模板不能删除历史 Run。

### 5.2 导出

支持：

- Markdown：面向人阅读。
- JSON：面向审计和后续工具。

两种导出必须来自同一权威 Run 快照，并包含：

- Run、模板版本和上下文
- Step、attempt、round 和状态
- Prompt、Conclusion 和 Review
- Decision 和用户动作
- Artifact 元数据和引用
- Error、等待原因和遗留边界

默认排除：

- 凭据和 Token
- 环境变量
- 未脱敏 Terminal transcript
- 本地或远程敏感路径中不必要的用户信息

导出需要显式用户动作；写入目标和覆盖行为遵循现有文件安全策略。

### 5.3 恢复算法

Runtime 启动时扫描：

```text
draft
ready
running
paused
waiting-human
review-limit-reached
```

每个 Run 按以下顺序恢复：

1. 读取最后持久状态和最后 Event。
2. 校验事件序号、Run 版本和模板快照。
3. 对照 Orchestration Run、Task、Dispatch 和 Worker。
4. 对照 Agent lifecycle、Provider Session、Pane 和 Execution Host。
5. 对照 delivery receipt、Step 结果和 Artifact Revision。
6. 执行唯一可确定的 Transition。
7. 不能确定时进入 `waiting-human`，记录证据和合法恢复动作。

恢复不得：

- 重复发送已 delivered 的 Prompt。
- 重复增加 Review round。
- 重复创建 Review Aggregate。
- 把旧 Dispatch 的迟到完成计入当前 Step。
- 把同 Pane 中的新 Agent 当成原 Agent。
- 把 Remote 断连直接标记为业务失败。

### 5.4 Delivery 幂等

唯一约束至少覆盖：

```text
(workflowRunId, stepRunId, attempt, deliveryKind)
```

交付状态：

```text
prepared → delivering → delivered
                     ↘ uncertain
                     ↘ failed
```

恢复规则：

- `delivered`：不重发。
- `prepared` 且没有外部 Dispatch：可安全继续发送。
- `delivering`：先检查 Dispatch、Worker 和 Agent 证据。
- `uncertain`：进入人工处理，不盲目重发。
- `failed`：仅通过显式 Retry 创建新 attempt。

数据库唯一约束、mutation ledger 和外部 Dispatch receipt 共同防重；不能只依赖 Renderer 按钮禁用。

### 5.5 Event 与完成去重

- Event 序号按 Run 单调递增。
- 相同外部消息 ID 只处理一次。
- `worker_done`、heartbeat、question、escalation 和 decision gate 必须关联正确 Dispatch。
- 旧 round、旧 attempt 和已取消 Run 的迟到消息只记录忽略原因。
- 状态更新、Aggregate/Decision 和 Event 在同一事务。
- 并发恢复进程必须通过 Run 版本或租约确保单一推进者。

### 5.6 长内容和 Artifact

- Prompt 和 Conclusion 超过消息阈值时，消息保存摘要并引用完整 Artifact。
- Copy 和 Workflow Handoff 读取同一持久化完整内容。
- 内容 Hash、digest 和长度用于完整性校验。
- Artifact 定位信息包含 Execution Host，不把远程路径当本机路径打开。
- 找不到 Artifact 时显示缺失状态和原始元数据，不伪造内容。
- 导出大内容时使用流式或有界内存实现，不阻塞 Renderer。

### 5.7 Git Worktree

验收：

- Run 永久绑定创建时的 Worktree 和 Execution Host。
- 并行写入节点使用不同 Worktree；Review 只读或隔离。
- Artifact 保存 Base SHA、Head SHA、Diff Hash 和未提交状态。
- 用户 Git 可能位于 native、WSL 或 SSH Host。
- 新增或修改的 Git 命令遵守 Git 2.25 基线。
- 新能力使用 `GitCapabilityCache`、窄 unsupported 谓词和 Host 隔离。
- 不使用 GitHub 专属概念表达通用 Review。
- 保留 `-c` 等位于子命令前的 Git 全局参数。

### 5.8 Folder Workspace

验收：

- 无 `.git` 时不请求 SHA、branch 或 Worktree。
- 使用文件清单、Hash、修改时间和快照表达 Artifact Revision。
- 写入节点默认串行。
- Review 通过快照和变更检测提供只读降级。
- Cancel、失败和恢复不删除或回滚用户文件。

### 5.9 SSH / Runtime Host

- Prompt 路由到 Worktree Owner Host。
- Assignment、Artifact、Dispatch 和 Event 都保存 Execution Host。
- Federation Run Home 是 Workflow 状态权威。
- Remote Worker 返回结果和 Artifact 引用，不要求本机文件存在。
- 断连时相关 Step 进入可恢复等待状态。
- 重连后先核对 Dispatch 与 lifecycle，再继续 Transition。
- Host A 的 capability、Pane、Agent 或 Artifact 不得污染 Host B。
- 无法提供某项能力时明确降级并阻止不安全操作。

### 5.10 UI 恢复

- 重启后 Workflows 合法页面选择可恢复。
- 活动 Run 自动出现在绑定工作区的 Workflow Activity。
- 用户切换到普通工作区仍可查看当前 Run 和等待决定。
- 恢复中的状态与证据可见，不先显示“完成”再回滚。
- 不确定状态提供“查看证据”“重试”“重新分配”或“结束”等合法动作。
- Run history 不依赖 Agent 仍在 Agent Activity 中。

### 5.11 数据库与启动

- 新库完整建表。
- 现有 Runtime SQLite 可迁移。
- 使用 WAL 时状态、Event 和唯一约束保持一致。
- 数据库文件和导出文件权限符合现有安全策略。
- 没有 Workflow 数据的老用户不产生明显普通启动性能回归。
- 损坏或未知 Workflow 数据不得阻止普通 Terminal、Tasks 和 Agent Activity 启动；隔离错误并提供诊断。
